# Ma-Ru — почта Mail.ru для агентов

Ma-Ru подключает почтовый ящик к Codex, Claude Code и OpenClaw. Попросите агента найти письмо с вложением, собрать переписку с заказчиком, пометить письма тегом или подготовить ответ. Для регулярных проверок плагин запоминает, какие письма задача уже обработала. Несколько ящиков можно подключить с разными правами.

Это независимый проект под Apache-2.0. Почтовое ядро, системное хранение паролей и механизм расписаний адаптированы из Ya-Ma. [Исходный проект Ya-Ma](https://github.com/grebennikovxyz/ya-mail-plugin) · [Лицензия](LICENSE)

Из описанных OpenAI сценариев Gmail здесь доступны сводка входящих, поиск по переписке, черновики ответов, архив, корзина и метки. Для Mail.ru добавлены режим доступа на каждый ящик и подтверждение полученных по расписанию пакетов. Особенности тегов разобраны в разделе «Почтовые операции». [Сценарии Gmail в ChatGPT](https://learn.chatgpt.com/use-cases/manage-your-inbox)

## Быстрый старт на Windows, macOS и Linux

Понадобятся Git и uv. Выполняйте команды под пользователем, от имени которого будет работать агент. uv подберёт Python 3.13. [Установка uv](https://docs.astral.sh/uv/getting-started/installation/) · [Установка Git](https://git-scm.com/downloads)

```sh
uv tool install --python 3.13 git+https://github.com/grebennikovxyz/ma-ru-plugin.git@main
uv tool update-shell
```

Откройте новый терминал и запустите мастер.

```sh
ma-ru connect
```

Чтобы сразу подключить **Codex**, выполните следующие две команды, затем откройте новый чат.

```sh
codex plugin marketplace add grebennikovxyz/ma-ru-plugin --ref main
codex plugin add ma-ru@grebennikov-ma-ru
```

Попросите «Покажи подключённые ящики. Для моего рабочего адреса покажи темы пяти последних писем во Входящих». При подключении нескольких ящиков укажите полный адрес. Варианты для Claude Code, OpenClaw и телефона описаны ниже.

## Мастер подключения

Для личного ящика Ma-Ru использует IMAP для чтения и папок и SMTP для отправки. Postmaster API пригодится владельцам доменов для статистики рассылок и жалоб на спам. Подключение Postmaster для сценариев этого плагина не требуется. [Документация Postmaster API](https://help.mail.ru/developers/postmaster/api/)

1. **Проверьте аккаунт.** Нажмите **Контакты и адреса**, войдите именно в подключаемый ящик и проверьте привязанный телефон. Mail требует привязанный номер для создания пароля внешнего приложения. [Контакты в Mail ID](https://id.mail.ru/contacts)
2. **Создайте пароль у Mail.** Нажмите **Создать пароль в Mail**. На странице **Пароли для внешних приложений** нажмите **Создать**, введите узнаваемое имя, например «Ma-Ru на домашнем сервере», затем **Продолжить**. Выберите **Полный доступ к Почте**, нажмите **Продолжить** и выполните подтверждение, если его предложит Mail. Скопируйте выданный пароль. Его можно увидеть один раз, а использовать для запланированных проверок — до отзыва. [Создать пароль](https://account.mail.ru/user/2-step-auth/passwords/) · [Инструкция Mail со скриншотами](https://help.mail.ru/mail/login/mailer/)
3. **Введите данные в мастер.** Укажите полный адрес вместе с доменом, в том числе для адресов на `bk.ru`, `inbox.ru`, `list.ru` и доменах организаций, обслуживаемых Mail. Вставьте сгенерированный пароль в скрытое поле. В чате пароль вводить не требуется.
4. **Выберите права агента.** По умолчанию включено чтение. Нажмите **Проверить и подключить**. Мастер проверяет вход и получает список папок. Если выбрана отправка, он также проверяет SMTP без отправки письма. После проверки пароль сохраняется в системном хранилище.

| Режим | Что получает агент |
| --- | --- |
| Только чтение | Поиск, содержимое писем и вложений, цепочки, счётчики и чтение новых пакетов по расписанию |
| Чтение, метки, папки и черновики | Также теги, звёздочки, прочитанность, перемещение, создание папок и редактирование черновиков |
| Также разрешить отправку писем | Все перечисленные действия и отправка через SMTP |

Режим действует внутри Ma-Ru. Права самого пароля определяет выбранный на сайте Mail тип доступа. Для изменения режима или добавления ящика снова запустите мастер. Проверить подключение без вывода содержимого писем можно так:

```sh
ma-ru status
ma-ru check your-address@mail.ru
```

Для Windows x64 есть автономный ZIP с Python и библиотеками в артефактах CI. Распакуйте его и откройте connect.cmd. Для ручного MCP укажите полный путь к runtime/python.exe и аргументы `-I -B -m ma_ru.cli serve`. На Windows в скачанной копии репозитория также можно открыть `connect.cmd`. Для компьютера без Tk доступен браузерный мастер `ma-ru connect --web`. Для SSH-сессии есть `ma-ru connect --terminal` со скрытым вводом пароля. На Linux требуется доступный Secret Service в сессии владельца ящика.

## Мои ящики, папки и ответы

Подключите адреса командой `ma-ru connect`. Попросите «Назови заказы на orders@example.org “Работа” и покажи сводку». `set_mailbox_name` задаёт имя, а `mailbox_overview` группирует письма по получившему ящику и папке. Адрес ящика сохраняется и у скрытых копий. Для быстрой проверки нескольких ящиков укажите в `scopes` нужные адреса и папки.

| Правило папки | Поведение |
| --- | --- |
| `priority` | Папка и её ветка попадают в начало обзора |
| `normal` | Участвует в обычном порядке |
| `skip` | Пропускается в общем поиске, сводке и расписании. Можно открыть явно |
| `blocked` | Вся ветка закрыта для поиска, чтения и изменений. Снять запрет можно с подтверждением владельца в интерактивном клиенте |
| `inherit` | Удаляет явное правило папки и возвращает унаследованный режим |

Правила задаются через `set_folder_rule`. По умолчанию учитываются Входящие и пользовательские папки. Архив, Отправленные, Черновики, Спам и Корзина пропускаются. Когда закрытая папка переименована, проверьте её новый путь и перенесите правило. До этого доступ к письмам этого ящика приостановлен. Для нескольких ящиков `poll_mailboxes` ведёт независимые пакеты и квитанции по каждой папке. Если появился новый почтовый каталог, существующее расписание увидит первое попавшее туда письмо.

`prepare_reply` создаёт черновик в получившем ящике и берёт адресата из Reply-To или From. Параметр `from_account` позволяет выбрать другой подключённый адрес. В ответе видны From, To, тема и ссылка на черновик. При отправке `send_draft` использует SMTP выбранного ящика и сохраняет связь с оригиналом через Message-ID, In-Reply-To и References.

### Вложения на Яндекс Диск и сроки в календаре

Подключите Ya-Di с правом записи под пользователем Ma-Ru. Укажите UID владельца Диска, существующую папку и фразы, например «просим рассчитать». `route_attachments` сначала показывает пути в режиме `preview=true`. Для сохранения передайте `preview=false`. При повторе плагин сверяет SHA-256 файла и узнаёт письма после перемещения. При заданном сроке результат содержит `calendar_request` для `create_event` плагина Ya-Cal. Календарное событие создаётся этим отдельным вызовом. [Ya-Di](https://github.com/grebennikovxyz/yandex-disk) · [Ya-Cal](https://github.com/grebennikovxyz/ya-cal-plugin)

## Ленивый разбор старой почты

Режим включается отдельно для каждого ящика. Он обрабатывает непрочитанные письма старше одного календарного года в порядке даты получения. По умолчанию выбраны Входящие. Для перемещения достаточно режима «Чтение, метки, папки и черновики».

```sh
ma-ru lazy preview --account your-address@mail.ru --limit 8
ma-ru lazy setup --account your-address@mail.ru
ma-ru lazy doctor --account your-address@mail.ru
ma-ru lazy digest --account your-address@mail.ru
```

1. В мастере выберите папки и отдельно разрешите чтение заголовков Отправленных. В первом проходе мастер просматривает заголовки выбранных папок: на большом ящике это может занять несколько минут. Он считает входящие и исходящие письма, разные цепочки и дни общения. Среди давних собеседников появятся люди, с которыми была двусторонняя переписка и последняя известная активность в просмотренной истории старше трёх лет.
2. Отметьте людей, переписку с которыми хотите сохранить. Можно вписать несколько точных адресов одного человека. Подтверждённая защита, звёздочка и история ответов имеют приоритет. Если проверить личную переписку невозможно, письмо останется на месте.
3. На примерах реальных рассылок выберите, от каких отправителей разрешено убирать чистую рекламу. По умолчанию новые отправители идут в **На согласование**. Даже у одобренной рассылки счёт, изменения доступа, вложение, неполный текст или сомнительное решение требуют согласования. В Корзину попадает только письмо одобренной рассылки с полностью проверенным рекламным содержанием. Место в ящике освобождается по правилам очистки Корзины Mail.ru.
4. Мастер покажет пробные решения перед сохранением. Правила и персональный `SKILL.md` остаются в каталоге данных владельца. Для изменения списка повторите `lazy setup`. Команда `ma-ru lazy disable --account your-address@mail.ru` отключает режим.

**Автоматический запуск с Codex.** Наблюдатель запускается после подтверждения настройки и при следующем старте MCP-сервера Ma-Ru. Он работает под пользователем владельца ящика. Введите в мастере идентификатор рабочего чата Codex. Поддерживаются стандартный локальный управляющий сокет, его точный путь и локальный WebSocket одного общего Codex App Server. Для WebSocket с авторизацией передайте наблюдателю Bearer-токен через переменную окружения `MA_RU_CODEX_TOKEN`. Если вы самостоятельно запускаете общий сервер, выберите адрес на loopback, включите `--ws-auth capability-token` и подключите к этому же адресу рабочий клиент через `codex --remote`. Наблюдатель можно запускать как пользовательский процесс командой `ma-ru lazy watch`. [Протокол Codex](https://developers.openai.com/codex/app-server/)

Ma-Ru начинает отсчёт 15 минут тишины после подключения. Он проверяет, что видит выбранный чат, состояния загруженных задач и оба окна лимитов одного аккаунта. Когда до сброса короткого окна остаётся меньше часа, до трёх обработчиков разбирают очередь всех включённых ящиков. Классификатор получает небольшие группы очищенных текстов одобренных рассылок. Выбирается доступная компактная модель Codex с низким уровнем рассуждения. Тексты вложений в запрос не входят. При новой задаче наблюдатель прерывает классификацию и прекращает выдавать перемещения.

При остатке 40% в начале окна целевой остаток составляет 4% полной квоты. Второй порог по умолчанию — расход одного процентного пункта недельного лимита. Для нескольких ящиков действует наименьший настроенный недельный предел. Начальные значения сохраняются между перезапусками. Телеметрия приходит с округлением и задержкой, поэтому обработчики оставляют запас. Если Codex сообщает только недельную квоту или рабочий чат запущен в изолированном процессе, автоматический разбор ждёт. `lazy doctor` показывает доступные окна и видимость чата.

**Ручной запуск.** В Claude Code или OpenClaw попросите вызвать `lazy_run` для конкретного ящика с бюджетом писем и токенов. Если клиент поддерживает MCP sampling, классификатор использует его модель. В остальных случаях потребуется установленный и авторизованный Codex CLI на хосте Ma-Ru. Эквивалент в терминале:

```sh
ma-ru lazy run --account your-address@mail.ru --max-messages 12 --token-budget 12000
```

Бюджет распределяется между обработчиками на весь ручной запуск. Ma-Ru консервативно резервирует размер отправляемого текста и место для ответа. Служебный контекст и учёт расхода определяет клиент модели. Ручной запуск применяет подтверждённые правила сразу, включая перемещение в Корзину. Для просмотра используйте `lazy preview`.

**Результат.** Дайджест доступен в чате через `lazy_digest` и в терминале через `lazy digest`. Раздел внимания включает темы и причины согласования. Можно запросить конкретный запуск по `--run ID`. После прерванного перемещения Ma-Ru сверяет обе папки по UIDVALIDITY, UID и Message-ID. При неоднозначном результате письмо попадёт в список для ручной проверки.

## Подключение клиентов

| Клиент | Где запускается Ma-Ru | Как проверить |
| --- | --- | --- |
| Codex | Локальный процесс на Windows, macOS или Linux | В новом чате вызвать `list_accounts` |

### Claude Code

```sh
claude plugin marketplace add grebennikovxyz/ma-ru-plugin
claude plugin install ma-ru@grebennikov-ma-ru
```

Для установки только MCP-инструментов в Claude Code или Codex есть прямые команды. Выберите один способ регистрации для каждого клиента, чтобы в нём появился один набор инструментов.

```sh
claude mcp add --scope user ma-ru -- ma-ru serve
codex mcp add ma-ru -- ma-ru serve
```

### OpenClaw

В репозитории есть готовый marketplace для OpenClaw. После установки команды `ma-ru` на хосте Gateway выполните `openclaw plugins install ma-ru --marketplace grebennikovxyz/ma-ru-plugin`. Также можно скачать архив и установить его в профиль Gateway. В актуальном OpenClaw локальный архив требует флага доверия источнику и согласия на запуск заявленного MCP-сервера. [Скачать архивы Ma-Ru](https://github.com/grebennikovxyz/ma-ru-plugin/releases)

```sh
openclaw plugins install ./ma-ru-0.3.0-clawhub.tgz --force --accept-capabilities
openclaw plugins inspect ma-ru
```

Установите Ma-Ru и подключите почту под системным пользователем Gateway. В актуальных версиях OpenClaw сервер добавляется в реестр MCP командами ниже. Подключайте его к личному агенту, которым управляет владелец ящиков. Пользователи с доступом к этому агенту могут воспользоваться его почтовыми правами.

```sh
openclaw mcp add ma-ru --command ma-ru --arg serve
openclaw mcp probe ma-ru
```

Эти команды с проверкой запускайте в профиле с остановленным Gateway. Если он уже работает, сохраните запись командой `openclaw mcp add ma-ru --command ma-ru --arg serve --no-probe` и проверьте инструменты в новой сессии агента. Отдельная команда `probe` проверяет запуск без обращения к модели.

При ручной настройке добавьте запись в существующий объект `mcp.servers`. Если служба не находит команду, укажите абсолютный путь, который возвращает `(Get-Command ma-ru).Source` в PowerShell или `command -v ma-ru` в Unix. После изменения конфигурации откройте новую сессию агента. [Реестр MCP OpenClaw](https://docs.openclaw.ai/cli/mcp) · [Настройки Gateway](https://docs.openclaw.ai/gateway/configuration-reference)

```json
{
  "mcp": {
    "servers": {
      "ma-ru": { "command": "ma-ru", "args": ["serve"] }
    }
  }
}
```

### Android и iOS

1. Подключите Ma-Ru к своему OpenClaw по инструкции выше. Пароль и состояние проверок остаются на хосте Gateway.
2. Откройте на телефоне **Chat** в Control UI личного OpenClaw через настроенный защищённый доступ. Войдите как владелец. Для iOS подходит также WebChat подключённого приложения OpenClaw. [WebChat](https://docs.openclaw.ai/web/webchat) · [Удалённый доступ к Gateway](https://docs.openclaw.ai/gateway/remote)
3. Выберите агента, которому доступен Ma-Ru. Попросите найти письмо в нужном ящике, затем прочитать его или подготовить черновик. Телефон можно закрыть, если расписание выполняет постоянно работающий Gateway.

**Как пройти мастер именно на телефоне.** В SSH-клиенте телефона включите локальный проброс порта 8766 на `127.0.0.1:8766` компьютера агента. В SSH-сессии запустите `ma-ru connect --web`. В браузере телефона откройте выведенный адрес `http://127.0.0.1:8766/`, пройдите по ссылкам на Mail и введите код мастера из терминала, адрес ящика и пароль приложения. Код действует для одного запуска. После успешного подключения форма закрывается. Для SSH-клиентов с командной строкой используйте команду ниже, подставив адрес своего хоста.

```sh
ssh -L 8766:127.0.0.1:8766 user@gateway.example.org
ma-ru connect --web
```

Вторую команду выполните **в открытой SSH-сессии**. При занятом порте используйте другой номер с обеих сторон проброса и `ma-ru connect --web --port НОМЕР`. Если ваш SSH-клиент не поддерживает проброс, в той же сессии используйте `ma-ru connect --terminal`. В мобильном приложении, которое принимает только встроенные коннекторы, доступен путь через чат Gateway.

### Личный HTTPS MCP для совместимых клиентов

Этот вариант пригодится, если мобильный или удалённый клиент поддерживает **Streamable HTTP** с заголовком **Authorization: Bearer**. Один экземпляр обслуживает одного владельца и даёт доступ ко всем ящикам, подключённым под его пользователем ОС. Для другого владельца нужны отдельная системная учётная запись, процесс и ключ.

1. Подключите ящик на хосте. Создайте отдельный случайный ключ, например через `python -c "import secrets; print(secrets.token_urlsafe(32))"`. Сохраните ключ в менеджере секретов, передайте процессу через переменную `MA_RU_MCP_TOKEN` и введите в поле Bearer клиента. Для этой переменной нужен ключ шлюза, а почтовый пароль вводится только в мастер.
2. На том же хосте выполните `ma-ru serve-http --public-origin https://mail-agent.example.org --port 8765`, подставив своё DNS-имя. Процесс слушает только `127.0.0.1`. Настройте HTTPS-прокси на этом хосте, чтобы он передавал `/mcp` на `http://127.0.0.1:8765/mcp`, сохраняя исходный `Host` и заголовок авторизации. Пример фрагмента для существующего TLS-блока nginx:

```nginx
location = /mcp {
    proxy_pass http://127.0.0.1:8765/mcp;
    proxy_http_version 1.1;
    proxy_set_header Host $http_host;
    proxy_set_header Authorization $http_authorization;
    proxy_buffering off;
}
```

3. Укажите в клиенте URL `https://mail-agent.example.org/mcp` и тип авторизации Bearer. Запросите `list_accounts`. Если клиент принимает только OAuth, используйте путь через OpenClaw. При ротации ключа обновите секрет сервиса и клиента и перезапустите Ma-Ru.

## Почтовые операции

| Что попросить | Инструменты и поведение |
| --- | --- |
| «Найди непрочитанные счета с вложениями от поставщика за ноябрь» | `search_messages`, `count_messages`. Фильтры по отправителю, To/Cc/Bcc, теме, тексту, Message-ID, датам, размеру, наличию вложений, тегу, звёздочке и прочитанности. Наличие вложений определяется по MIME-структуре без скачивания файлов. |
| «Собери всю переписку по этому письму» | `read_thread` связывает письма по Message-ID, In-Reply-To и References. `read_message` и `read_messages` читают текст без изменения прочитанности. При `index_complete=false` повторите вызов, чтобы продолжить построение индекса. |
| «Покажи приложенный счёт» | `read_message` перечисляет MIME-части, `read_attachment` читает выбранную часть порциями base64. Для полного чтения исходного письма действует предел 32 МиБ, для одной порции вложения — 512 КиБ. |
| «Поставь тег “К оплате”, отметь звёздочкой» | `list_labels`, `create_label`, `modify_messages`. Пакет до 100 писем из одной папки. Прочитанность и звёздочка записываются на сервер. |
| «Перенеси обработанные заявки в Архив» | `list_folders`, `create_folder`, `move_messages`. Доступны системные роли архива, спама и корзины или явное имя папки. При отсутствии системного архива можно создать свою папку и выбрать её по имени. |
| «Подготовь ответ, дай прочитать и после моего указания отправь» | `list_drafts`, `create_draft`, `update_draft`, `send_draft`, `send_email`. Поддерживаются To/Cc/Bcc, вложения, ответы с привязкой к оригиналу, пересылка как EML. Для удаления черновика перенесите его в корзину. |
| «Каждый день утром разбирай новые письма» | `poll_new` и `acknowledge_batch` предоставляют исполнителю расписания повторяемую выдачу и подтверждение пакетов. |

**Метки.** Если папка принимает пользовательские IMAP keywords, плагин записывает метку в ящик и проверяет результат. Для кириллицы и пробелов используется обратимое кодирование. Вид в веб-интерфейсе Mail и других клиентах зависит от их поддержки keywords. Если папка объявляет, что пользовательские флаги сохранить нельзя, плагин сохраняет тег у исполнителя и возвращает имя в `local_labels`. Оба вида доступны через `filters.label`. Локальный тег связывается с Message-ID в пределах ящика и виден у копий с тем же ID после перемещения. У сообщения без Message-ID привязка действует для текущих папки, UIDVALIDITY и UID. Для синхронной работы с телефона и компьютера используйте один Gateway.

**Поиск.** `since` включает начальную дату, `before` исключает конечную. Используются даты получения IMAP. Поиск без явной папки обходит активные папки, начиная с приоритетных. Внутри папки результаты идут от новых UID к старым. Для следующей страницы передайте `next_before` с прежними фильтрами. Bcc можно найти только у тех писем, где соответствующий заголовок доступен в ящике. Для письма без связующих заголовков используйте поиск по теме и участникам.

**Черновики и отправка.** `update_draft` принимает новую версию письма целиком вместе с нужными вложениями, сначала сохраняет её, затем переносит исходную в корзину. Если результат содержит `original=check_original`, новая версия сохранена, а исходную следует проверить. Повтор с тем же исходным идентификатором и содержимым защищён от дублей. При отправке нового письма сохраняйте один `request_id` (UUID) на одно поручение. `accepted` означает приём SMTP-сервером по указанным адресам. При потере ответа проверьте письмо по Message-ID перед новой попыткой. После `send_draft` исходный черновик остаётся в папке до явного перемещения.

## «Запланированное» и автоматизации

Для настольного ChatGPT с поддержкой локальных плагинов выберите исполнение **на этом компьютере**, подключите Ma-Ru к чату, выполните первый запрос и задайте время повтора. В локальном Codex выберите Ma-Ru для автоматизации. Поддержка плагинов и облачного запуска зависит от клиента и рабочего пространства. Встроенное событие Gmail «новое письмо» специфично для Gmail. Ma-Ru проверяет Mail.ru по таймеру. Компьютер, клиент-исполнитель и системное хранилище должны быть доступны к моменту запуска. На постоянно работающем OpenClaw то же поручение можно дать личной cron-задаче. [Запланированные задачи с плагинами](https://developers.openai.com/training/walkthroughs/scheduled-tasks) · [Расписания ChatGPT](https://help.openai.com/en/articles/10291617-scheduled-tasks-in-chatgpt) · [Cron OpenClaw](https://docs.openclaw.ai/automation/cron-jobs)

Пример текста задания:

> По будням в 09:00 по Москве проверяй INBOX ящика orders@example.org. Вызови poll_new с feed orders-morning. Для каждого письма о заказе укажи отправителя, тему, срок и названия вложений. После обработки всего пакета вызови acknowledge_batch с полученным receipt. Если has_more=true, продолжай до конца. Отправь мне сводку, когда есть новые заказы.

Первый вызов по умолчанию ставит начальную позицию на текущий конец папки. Выполните его при настройке, чтобы учесть письма, пришедшие до первого срабатывания таймера. Для разбора накопленной почты укажите `include_existing=true` в самом первом вызове. У каждой тройки **ящик + папка + имя feed** своя позиция. Подтверждайте каждый выданный `receipt`, в том числе если письма исчезли из папки за время обработки. При сбое неподтверждённый диапазон придёт повторно. Для внешних действий используйте постоянные ключи операций. При смене UIDVALIDITY проверьте затронутый период и заведите новое имя feed.

## Данные, отключение и диагностика

Соединения с Mail используют TLS с проверкой сертификата на `imap.mail.ru:993` и `smtp.mail.ru:465`. Пароль хранится в Windows Credential Manager, macOS Keychain или Linux Secret Service. В каталоге данных `MaRuMailPlugin` находятся SQLite-база с адресами, правами, тегами, контрольными позициями, хешами заголовков и квитанциями операций. Тексты и вложения передаются агенту по запросу. История чата и результаты задач хранятся по правилам выбранного клиента.

```sh
ma-ru disconnect your-address@mail.ru
```

Команда удаляет локальное подключение, его пароль и данные задач. Чтобы отозвать пароль у провайдера, откройте **Пароли для внешних приложений**, выберите выданное Ma-Ru имя и нажмите **Удалить**. [Отзыв пароля](https://help.mail.ru/mail/login/mailer/#delete)

| Симптом | Что проверить |
| --- | --- |
| Mail отклоняет вход | Полный адрес с доменом, привязанный телефон, пароль именно от внешнего приложения и тип «Полный доступ к Почте». Права администратора корпоративного ящика могут ограничивать доступ. |
| Мастер работает, агент видит пустой список | Оба процесса должны работать под одним пользователем ОС на одном хосте. На Linux службе нужны та же D-Bus-сессия и разблокированный Secret Service. |
| Клиент не видит команду | Перезапустите клиент после изменения PATH или укажите абсолютный путь к исполняемому файлу. Откройте новый чат и проверьте `list_accounts`. |
| Первая проверка ничего не вернула | Обычный первый вызов ставит начальную позицию. Для проверки отправьте себе тестовое письмо после инициализации или создайте отдельный feed с разбором накопленной почты. |
| HTTP вернул 401, 403 или 421 | Проверьте соответственно Bearer-ключ, заголовок Origin и сохранение внешнего Host на прокси. |

## Проверка из исходного кода

```sh
git clone https://github.com/grebennikovxyz/ma-ru-plugin.git
cd ma-ru-plugin
uv run --python 3.13 --with pytest pytest -q
uv run --python 3.13 python scripts/package.py
```

Тесты используют временную базу и синтетические письма. Они проверяют в том числе IMAP с кириллическими поисковыми строками, TLS-параметры, права, повторную отправку, черновики, теги, восстановление расписаний, MCP stdio и авторизацию HTTP. CI запускает набор на Windows, macOS и Linux. Дополнительно браузеры Chromium и WebKit отправляют форму мастера в эмуляции Pixel и iPhone. Архив в `dist/` содержит манифесты, инструкции агента и README. На хосте для него нужна установленная команда `ma-ru`. Для проверки реального аккаунта пройдите мастер и выполните `ma-ru check`. [Запуски CI](https://github.com/grebennikovxyz/ma-ru-plugin/actions)
